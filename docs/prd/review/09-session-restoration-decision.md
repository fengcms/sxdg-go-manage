# 刷新恢复登录：需求调整记录

日期：2026-10-04。依据：用户明确要求优化管理后台刷新后重新登录的问题。本次授权覆盖旧 PRD 的“令牌纯内存、刷新重新登录”约定；后端接口与权限规则不变。

## 采用方案

- 双令牌与有效期保存在当前源、当前标签页的 sessionStorage。密码、角色、用户详情和业务缓存不持久化。
- 页面启动先恢复令牌、请求 auth/me，再开放路由。以服务端返回的管理员身份和角色为准，不直接信任浏览器缓存的权限。
- 访问令牌过期通过现有 auth/refresh 轮换双令牌并同步存储。并发恢复只发起一次身份校验；旧会话响应不回填新会话。
- 刷新后保留路径和 URL 筛选条件；未提交表单内容仍不承诺保存。
- 401/403 身份失败清理会话，回到登录页。临时网络故障、限流或服务端失败保留令牌，在恢复页展示重试与返回登录，不显示业务页面。
- 主动退出清除当前标签页令牌和查询缓存。独立标签页不共享登录状态，浏览器复制标签页或会话恢复行为由浏览器决定，不承诺关闭窗口一定销毁会话。
- 浏览器禁用存储时仍可在内存中登录，但无法保证刷新保持。

## 取舍与范围

sessionStorage 满足刷新连续性，同时避免改造现有 Bearer 双令牌接口。与所有可由 JavaScript 读取的存储一样，需要持续维护 XSS 防护。此次不新增跨标签页同步或长期“记住我”，不修改后端令牌有效期，不改冻结后端文档，也无需数据库迁移。

旧验收报告与开发流水账中的“纯内存/刷新登录”为当时实现记录，从本决策起被上述行为替代。
