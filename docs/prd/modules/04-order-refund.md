## 0. 首期数据来源总则（S03 冻结）

订单/退款/服务/需求的列表与详情均为**后端单行模型直出**（`admin.go:AdminRead`，不 join 关联表）。因此：

1. **逐列/逐字段标注数据来源**：本文所有展示项按三类标注——「✅ 单行模型已有」直接展示；「❌ 后端无此数据」首期**移除或降级**；「⏳ #4 聚合 DTO」为后端任务 #4（订单/退款详情聚合 DTO，P1）就绪后回填的展示项
2. **交易双方（雇主/服务者/申请人/发布者）首期仅展示用户 ID + 跳转链接**（跳用户详情）——单行模型只有 ID 字段，无昵称/头像，**禁止前端猜值、禁止显示空头像占位伪装**；昵称/头像回填**仅限详情页**（#4 聚合仅详情接口）——**订单列表首期维持双方 ID 展示，不做批量摘要**（T06 冻结：不新增批量摘要接口）
3. **禁止逐行 N+1 请求补数据**（如逐订单再请求用户接口拼昵称）；**禁止前端按当前费率配置现场推导**任何金额（如「服务者结算金额」）
4. 「以后端返回为准」不足以指导开发的地方，本文逐节明确缺失字段的首期呈现方式（不渲染 / 仅 ID / 占位说明）

### 2.2 状态操作（固定动作，无通用状态下拉）

> **不提供通用状态修改下拉**。仅按当前状态渲染以下两个固定动作按钮，其余状态**不渲染任何状态操作**：

| 动作按钮 | 显示条件 | 流转 | 必填 | 交互 |
|----------|----------|------|------|------|
| 取消未支付订单 | 当前状态 = 0（待支付） | 0 → 6 | `reason` | 二次确认 + 原因输入 |
| 验收完成 | 当前状态 = 4（待验收） | 4 → 5 | `reason` | 二次确认 + 原因输入 |

- 接口：`PUT /api/v1/admin/orders/:id/status`，Body：`{ "status": 6, "reason": "..." }` / `{ "status": 5, "reason": "..." }`
- 其余状态流转后端拒绝，前端**只渲染上述两个动作按钮**
- 权限：仅 customer_service / super_admin 可操作

### 2.3 Tab 分区（首期缩减）

| Tab | 内容 | 状态 |
|-----|------|------|
| 基本信息 | 雇主 / 服务者（仅 ID + 跳转链接）、服务内容、预约时间、服务地点、金额明细 | 首期 |

> **移至二期**（后端详情聚合/子资源接口，任务单 #4）：履约记录 Tab、状态时间轴 Tab、退款记录 Tab、评价 Tab。首期不渲染，禁止 N+1 拼凑。

### 2.4 金额明细（逐项标数据来源）

**只展示订单单行模型已有的快照字段，不按当前配置现场重算**：

| 项目 | 说明 | 数据来源 |
|------|------|---------|
| 订单总额 | 订单快照字段 | ✅ 已有（`amount`） |
| 平台服务费 | 按下单时费率冻结的值 | ✅ 已有（`serviceFee`） |
| ~~服务者结算金额~~ | **首期移除** | ❌ 后端无该字段（订单模型无独立「服务者结算」字段，也**禁止按当前费率现场推导**）；⏳ #4 聚合 DTO 就绪后展示**结算对象及状态**（T06 冻结语义，见下） |

> 服务费比例、分摊以订单创建时冻结的快照为准；修改系统费率配置不影响存量订单展示，**前端不按当前配置重算**。结算展示语义（T06 冻结）：#4 聚合 DTO 返回**结算对象及状态**——结算记录 `status=0` 为**待结算**、`status=1` 为**已入账**；**无结算流水返回 null，展示「暂无结算」**；**不把待结算金额标作实收**。DTO 就绪前**不渲染该行、不显示推导值**。

## 3. 退款审核 `/refunds`

> finance / customer_service / super_admin 可查看；审核操作仅 finance / super_admin。

### 3.1 筛选栏（首期最小集合）

| 筛选项 | 类型 | 说明 |
|--------|------|------|
| 退款状态 | 下拉 | 全部 / 处理中 / 已同意 / 已拒绝 / 平台审核中 / 已完成 / 已撤销 |

> 关键词 / 申请人角色 / 申请时间筛选为**二期**（后端任务单 #3）。当前后端仅支持 `status` 筛选。

### 3.2 表格列（逐列标数据来源）

| 列 | 说明 | 数据来源 |
|----|------|---------|
| 退款单号 | 点击跳转详情 | ✅ 已有（`refundNo`） |
| 来源 | **订单退款 / 需求流拍徽标 + sourceId**：`sourceType=0` → 跳订单详情 `/orders/:sourceId`；`sourceType=1` → 跳需求详情 `/requirements/:sourceId` | ✅ 已有（`sourceType` / `sourceId`）；**关联订单号/订单金额 ❌ 无数据**（需 join orders，⏳ #4 聚合 DTO 就绪后回填） |
| 申请人 | **仅展示用户 ID + 跳转链接**（跳 `/users/:applicantId`） | ⚠️ 仅有 `applicantId`；昵称/头像 ⏳ #4；**无申请人角色列**（后端无该字段） |
| 退款金额 | 十进制字符串 | ✅ 已有（`applyAmount`） |
| 状态 | 状态徽标 | ✅ 已有（`status`） |
| 申请时间 | | ✅ 已有（`createdAt`） |
| 操作 | 审核（仅退款状态 0 / 3）/ 查看 | — |

> **来源导航规则（S03 冻结）**：退款来源含**需求流拍（`sourceType=1`）**，不能一律按 `sourceId` 链接到订单——`sourceType=1` 的退款**必须跳需求详情**，跳订单详情是错误跳转。原「关联订单（订单号 + 金额）」列首期移除（单行模型无 join 数据），#4 聚合 DTO 就绪后回填为「关联单号 + 金额」。

> **裁定范围（冻结）**：仅退款状态 **0（处理中）/ 3（平台审核中）** 可裁定，其余状态不渲染审核按钮。

### 3.3 退款详情 `/refunds/:id`（首期呈现，按单行模型）

```
┌────────────────────────────────────────┐
│ 退款单 #R20261004001        状态：平台审核中 │
├────────────────────────────────────────┤
│ 来源：订单退款 → 订单 #12345（跳转）        │  ← sourceType=0 跳订单详情；
│                                        │     sourceType=1 显示「需求流拍 →
│                                        │     需求 #sourceId」跳需求详情
│ 申请人：用户 #67890（跳转）                  │  ← 仅 ID + 跳转链接，无昵称头像
│ 退款金额：¥200.00                         │  ← applyAmount（单行模型已有）
│ 申请时间：2026-10-04 10:00                │  ← createdAt
│                                        │
│ 退款原因：服务者迟到 2 小时                 │  ← reason
│                                        │
│ （处理时间线首期不展示：单行模型无逐步       │
│   处理事件数据，⏳ #4 聚合 DTO 就绪后回填）  │
│                                        │
│ 裁定意见：[________________________]      │  ← 通过/拒绝均必填
│ 裁定金额：[¥______]（可选，≤ 申请额）        │  ← 仅通过时展示
│                                        │
│        [拒绝]      [裁定退款]              │
└────────────────────────────────────────┘
```

> **首期移除的展示项（S03）**：①「关联订单号 + 订单金额」（需 join orders，⏳ #4）；②「处理时间线」（申请→拒绝→平台介入等逐步事件，单行模型无此数据，⏳ #4）；③申请人昵称/头像（仅 ID + 跳转，⏳ #4）。以上均**不虚构、不从单行字段推导历史事件**。

### 3.4 裁定操作

| 操作 | 接口 | 请求体 | 校验 |
|------|------|--------|------|
| 裁定通过（裁定退款） | `POST /api/v1/admin/refunds/:id/approve` | `{ "reason": "...", "finalAmount": "180.00" }` | **reason 必填**；`finalAmount` 可选且 **≤ 申请金额** |
| 裁定拒绝 | `POST /api/v1/admin/refunds/:id/reject` | `{ "reason": "..." }` | **reason 必填** |

> **通过也必须填写 reason**（后端强制）；`finalAmount` 用于部分退款裁定，超出申请额前端直接拦截并提示。

> 后端退款状态机详见 `enums.md §6`。

## 6. 后端接口契约摘要（对齐 api-integration.md v4）

### 订单

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/admin/orders` | 列表（Query 仅 `status` / `page` / `page_size`；其余筛选二期） |
| GET | `/api/v1/admin/orders/:id` | 详情（单行模型，不含履约记录 / 状态日志聚合，二期任务单 #4——聚合就绪后含**结算对象及状态**：status=0=待结算、1=已入账，无流水返回 null 展示「暂无结算」，不把待结算金额标作实收） |
| PUT | `/api/v1/admin/orders/:id/status` | Body：`{ status, reason }`；**仅两个合法流转**：取消未支付 0→6、验收完成 4→5，均必填 reason |

### 退款

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/admin/refunds` | 列表（Query 仅 `status` / `page` / `page_size`） |

| POST | `/api/v1/admin/refunds/:id/approve` | Body：`{ reason, finalAmount? }`；**通过也必填 reason**；finalAmount ≤ 申请额 |
| POST | `/api/v1/admin/refunds/:id/reject` | Body：`{ reason }`；拒绝必填 reason |

> 裁定范围：仅退款状态 0/3 可裁定。

### Service / Requirement

| 方法 | 路径 | 说明 |
