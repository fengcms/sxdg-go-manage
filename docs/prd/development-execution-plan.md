# 管理后台开发执行计划（草案）

日期：2026-10-04。依据：现有 PRD、四轮产品裁决、后端 A/B 批次交付（提交 `a2085e1`）。本文补充原 development-plan.md 的执行安排，不替代产品范围裁决。本次仅交付计划，尚未开始前端编码。

## 1. 开工结论

**已具备首期管理后台的开发和本地联调条件。** 登录、四角色授权、用户治理、资质队列、内容维护、交易处理、客服基础查询/流转、配置与审计所需的后端补充能力已经实现。无需等待 IM 和新版看板再启动前端。

目前 sxdg-manage 仓库只有 Git 与 docs，尚无 package.json、锁文件或前端应用；需要从工程初始化开始。后端已完成单测、真实 PostgreSQL/Redis 集成测试及部分 curl 验证；这不等于管理后台页面已验收，仍需逐页四角色联调。

后端交付参考：[交付说明](../../../sxdg-be/docs/review/admin-backend-supplement-delivery.md)、[API §18](../../../sxdg-be/docs/api-spec.md)、[PR #2](https://github.com/fengcms/sxdg-be-go/pull/2)。当前实现可本地联调；共享集成环境应使用包含密码登录、服务费配置及 A/B 补充提交的版本，不能直接假设主分支已包含所有能力。

## 3. 交付范围

### 首期：可操作的本地管理后台

- 登录、退出、纯内存令牌、四角色菜单/路由/按钮权限，中文界面与错误提示。
- 四类现有看板，按真实统计口径展示，无趋势图或日期筛选。
- 用户列表与基本资料、封禁/解封、信用分调整、资质审核及鉴权证件查看。
- 三级分类、热门聚合入口创建/删除、动态表单 JSON 编辑/校验/预览、Banner 与分类图片上传、服务标签。
- 订单列表/详情、固定状态动作、退款审核、服务/需求查询与上下架/关闭。
- 客服配置绑定、在线状态、接待会话列表、转接、参与方已入库消息查看。无聊天发送输入框。
- 系统配置、信用规则、服务费配置、操作日志。使用已实现的审计中文标签与操作人摘要。

### 增强批次：后端已就绪，建议首期验收后追加

现有产品文档将这些展示项列为二期；若产品选择提前纳入，可在对应模块开发后实施并增加验收工作量：

- 高级筛选：完整手机号精确查询、用户身份、日期区间、订单交付类型、退款申请方身份等；仅使用各接口明确支持的参数。
- 用户信用记录与发布服务/需求 Tab；不扩展为尚未约定的用户交易 Tab。
- 订单详情双方摘要、真实结算对象与状态、关联退款；退款详情来源摘要。订单列表继续展示双方 ID，不逐行请求用户详情。
- 热门分类修改与排序，使用 PUT，不用删除重建。

### 本轮不包含

IM 文本/图片发送、完整供应商聊天历史、已读/实时推送；新版看板；可视化表单编辑器；管理员页面开户；任务/勋章/活动消息运营页面；生产部署。这些继续遵循原产品范围，不以占位页面计作完成。

## 4. 开发顺序和阶段成果

沿用原 Phase 0～7 顺序。每一阶段完成后检查、提交并提供可复查的页面或演示步骤。

| 阶段 | 主要工作 | 阶段验收 |
|---|---|---|
| 开发准备 | 同步合同、确认后端版本、准备四角色账号和隔离业务数据；列出页面/API/权限矩阵 | 每个首期操作均有明确接口、字段和角色；不存在假接口 |
| Phase 0 工程与 UI 基础 | 按已定 React 19/Vite/TS/Tailwind v4 技术栈初始化；锁定运行时与依赖；Biome、测试、代理、中文布局、公共表单/表格/反馈组件 | 可启动、构建；/api/v1 和 /uploads 同源代理可用；加载/空/错态统一 |
| Phase 1 登录与权限 | 内存会话、refresh 同飞、auth/me 校准、权限守卫、退出与换用户隔离 | 四角色可登录；越权拒绝；刷新页面重新登录；旧请求不回填新会话 |
| Phase 2 看板 | 四个现有统计页面、金额格式、口径说明 | 数值与后端一致；空数组不补假数据；财务页角色隔离 |
| Phase 3 用户与资质 | 用户查询/详情、封禁、信用调整、资质审核、证件 Blob 查看 | 审核和封禁后重新拉取状态；原因必填；证件无公开直链；无权限按钮隐藏 |
| Phase 4 内容运营 | 分类全分页构树、热门入口、模板 JSON 编辑与预览、Banner/标签/上传 | 三级约束与引用删除保护；模板五种字段类型和嵌套 panel 正确；图片上传后可展示 |
| Phase 5 交易管理 | 订单/退款、服务/需求、固定状态动作与确认弹窗 | 仅合法动作；退款金额与理由校验；流拍退款跳需求；需求关闭无伪恢复 |
| Phase 6 客服基础 | 绑定管理、本人身份、在线状态、会话列表、流转、已入库记录查看 | 未绑定/停用状态明确；agentId 不混 userId；非参与超管不能读消息或代转；转接后清除旧消息 |
| Phase 7 配置与审计 | 系统参数、信用规则、费率分摊、操作日志 | 十进制金额与整数百分比校验；信用组合约束；危险操作确认；审计可追溯 |
| 首期验收 | 四角色全流程、异常响应、会话竞争、浏览器布局/键盘操作；交付运行说明和缺陷清单 | 四项工程门禁通过，业务矩阵逐项有证据，未通过项明确列出 |
| 可选增强 | 上节列出的 B 批次前端展示能力 | 分别验证全量筛选、聚合字段、空结算和热门 PUT，不扩大到其他二期事项 |

不把各阶段合并成一次大提交；测试与接口联调随模块开展，末阶段做跨模块回归。

## 5. 实现与测试约束

1. 沿用产品已定技术栈；具体兼容版本在初始化安装、类型检查和构建后锁定，不在本计划中假定最新版兼容。
2. API 层显式定义 DTO；分页请求 page/page_size、响应 items/total/page/pageSize。看板和 fee-config 的 snake_case 不做全局转换。
3. 令牌不写 localStorage/sessionStorage/Cookie；登录和 refresh 不自动触发再次刷新；退出取消请求、清缓存，并用会话标识阻止旧响应回填。
4. 权限表统一驱动路由、菜单和按钮；页面间跳转也检查目标权限。后端 403 作为最终授权结果处理。
5. 金额使用十进制字符串与 decimal；费率分摊展示雇主承担百分比，拒绝 30.5% 等超出冻结精度的输入，不静默取整。
6. 日期筛选按上海时区解释，结束日包含全天；由服务端使用下一日零点排他边界。分页/筛选写 URL，重登后可恢复查询条件但不恢复敏感缓存。
7. 客服界面明确标注“已入库消息记录”；无消息不等于无完整 IM 历史，不展示伪未读数或虚假发送成功。
8. 不支持的筛选不渲染；分类构树读取全部分页；未知枚举保留原值并给出中文兜底说明。

每阶段执行：

```bash
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

单测重点为权限映射、请求刷新并发、金额转换、模板校验、分页参数和错误处理；真实浏览器与 HTTP 联调用于验证 CRUD、角色隔离、图片、状态流转及审计。后端修改发生时补跑相应 Go 测试。

联调使用真实后端 HTTP、PostgreSQL、Redis 和四角色账号；外部微信/短信/IM mock 必须在报告记录。准备待审资质、可转接会话、待裁定退款、不同订单状态及有引用分类等隔离数据，不用前端假响应替代业务验收。

## 6. 仍缺什么，是否阻塞

| 项目 | 当前状态与处理 | 是否阻塞首期 |
|---|---|---|
| PRD 与后端交付状态同步 | 上述旧描述需修正；开发准备阶段可完成，不需要重新发明契约 | 不阻塞启动，相关页面编码前完成 |
| 前端工程、组件实现、锁文件 | 仓库尚未初始化；技术指导的参考组件源码未交付，按约定自行实现 | 属于开发工作，不需要额外资料 |
| 四角色和业务数据 | 已有初始化命令及部分冒烟数据；仍需为每个页面补充可重复的隔离场景 | 联调前准备，无需等待生产数据 |
| 后端共享版本 | 本地已交付；PR 审阅合入与共享环境部署仍需走交付流程 | 本地可开发，共享联调时核对版本 |
| IM 合同与真实环境 | 草案尚待评审；需决定发送权威、历史范围、转接后阅读边界、持久化迁移，随后提供供应商凭据及公网回调环境 | 仅阻塞 IM 增强 |
| 新看板指标 | GMV 退款/取消处理、活跃定义、趋势粒度与时间范围待产品确定 | 仅阻塞新版看板 |
| 生产部署方案 | 域名/HTTPS、反向代理、SPA 回退、证件访问、配置与日志收集、发布回滚待部署阶段明确 | 不阻塞本地首期，不宣称已经可上线 |

IM 讨论入口：[IM 合同草案](../../../sxdg-be/docs/review/admin-im-contract-draft.md)。首期无需用户补齐这些二期内容。

## 7. 工作量和交付方式

原产品计划约 11 个单人工作日可作为首期粗估参考，不能当作已验证的交付日期。仓库从零初始化、动态表单预览和四角色回归是主要不确定项；完成 Phase 0～1 后按实际进度修订。可选增强另计，生产部署与真实 IM 联调不含在首期估算中。

最终交付：前端源码与锁文件、启动说明、环境示例（不含凭据）、中文操作界面、四角色验收报告、已知限制与后续任务清单。首期完成标准是本地真实后端可操作且业务验收通过，不是仅构建成功。
