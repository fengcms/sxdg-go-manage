# 登录刷新恢复流水账

## 2026-10-04

- 用户反馈刷新就回登录，不符合后台连续操作预期。确认原因：原 PRD 指定纯内存令牌，页面刷新即丢失。不是后端令牌立即过期。
- 决定使用 sessionStorage 保存双令牌，不保存密码和角色。另写 review/09-session-restoration-decision.md 记录覆盖旧约定，README 与当前对接矩阵同步。
- auth store 的登录、轮换、清理统一同步存储；启动恢复先请求 me，完成前不挂载路由，避免闪登录和未校验权限页面。
- StrictMode 会重复运行 effect，恢复 Promise 共用一次请求；现有 epoch 检查继续隔离退出后/换账号后的旧响应。
- 排查发现原 refresh catch 对任何异常都清会话。改为只在明确 401/403 清理，断网/503 可保留会话重试。
- 重试计数是 effect 的显式触发器，Biome 误认为多余依赖；局部注释说明原因，不关闭全局规则。
- 新增存储与恢复单测；原四角色浏览器用例从“刷新需登录”改为“刷新保持路由”。补真实后端验证失效 access token 自动续期、退出、双令牌失效、恢复断网重试。
- 验证：pnpm check 通过（类型检查、Biome、11 个测试文件共 67 项单测、生产构建）。Chromium 首轮 19 项中 15 项通过，财务登录命中“操作频繁”，另三项出现页面等待超时；未改业务代码，用 --last-failed 重跑四项全部通过（11.3 秒）。不能将首轮写成全绿。新增三项会话场景首轮全绿，四角色刷新、退款、客服和 Banner 回归最终均通过，亮暗截图基线无变化。
- 本地验收生成独立前缀账号与业务记录，保留审计；凭据与运行报告均在 Git 忽略目录，未加入提交。
- 最后复查发现 Biome 的 *.json 范围会读入新生成的忽略夹具，格式诊断可能带出本地测试凭据；将两份 .e2e JSON 显式排除。源码仍全量检查，不对凭据文件运行格式化。
