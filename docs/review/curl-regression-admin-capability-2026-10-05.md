# 2026-10-05 curl 回归涉及的管理后台能力核对

核对日期：2026-10-05。对象：`sxdg-be/docs/demo/curl-regression-2026-10-05-203705.md` 中实际出现的管理员操作，与当前 `sxdg-manage` 页面、路由、权限及 API 对接代码。

## 结论

回归涉及的日常人工动作大多已有后台入口：内容与系统配置、资质审核、用户封禁/解封、人工调分、退款裁定、客服代订单验收、看板、订单筛选和操作审计。全局资质队列也已经接通，因此本报告按当前实现判断，不沿用旧 PRD 中关于队列待后端补齐的过时说明。

存在一个明确缺口：回归实际验证了“退款主动对账终态幂等”，后端 API 基线有退款查单对账接口，但后台退款详情没有“对账”操作入口。若管理员需要从后台完成该项运维闭环，应补上入口与结果展示。当前后台只有汇总看板和订单详情中的结算只读展示；回归中的自动结算、自动提现没有对应人工处理步骤，也没有在本轮回归中证明存在人工资金操作需求。

## 建议补充项

### 必须补：退款主动对账入口

- 在退款详情中加入「主动对账」，仅财务/超管可操作，并遵循后端 `POST /api/v1/admin/refunds/:id/reconcile` 契约。
- 请求填写 1～255 字原因；操作前展示退款号及来源对象，操作后刷新退款状态。
- 展示 `status`、`channelStatus`、`retryCount`、`lastRetryAt` 和退款 attempts 历史（若当前详情 API 返回）。明确这是查询微信通道状态，不允许人工伪造成功。
- 若后台确需支持失败重试，同一页面再按接口状态增加 retry 操作；重试与 reconcile 是不同动作，不能把查单按钮当成重试。
- 覆盖财务/超管可用、运营/客服不可用，以及幂等重复查单的浏览器验收。

### 建议补：资金核对可观测性

本轮回归特意核验总账余额、结算流水与钱包流水一一对应、提现/退款无待处理单据。后台目前的财务看板只有汇总金额；订单详情可读单笔结算，但没有跨订单结算流水、钱包流水、提现单和退款渠道 attempts 的统一筛选/导出或勾稽视图。若财务希望这些回归断言可在日常工作台中复核，建议新增只读「资金对账」页面，至少支持日期/状态/用户/业务单号筛选，展示结算、钱包入账、提现和退款渠道记录及差异提示。此项属于运营能力增强，当前回归未要求人工修改资金状态。

## 权限与页面路径说明

- 前端菜单角色来源为 `sxdg-manage/src/config/navigation.ts`，动作权限为 `sxdg-manage/src/lib/permission.ts`；路由守卫与按钮动作均校验角色。
- `navigation.ts` 对系统设置的角色数组写为空，但 `allowed()` 明确将 `super_admin` 视为全权限，因此超管菜单仍显示；运营、财务、客服被路由守卫导向 403。以当前代码行为为准。
- 回归负向验证的是后端真实权限拒绝；UI 隐藏/403 仅是体验层，服务端权限仍是安全依据。
- 后台没有管理员账号开通页面；四个角色账号由现有运维/初始化流程提供。这不是该 curl 批次中的具体管理员业务动作缺口。
